# AEONFALL ∞ — COMPLETE UNIVERSE, SOURCE FIRST

**Creator directive (2026-11-01):** Complete the planned AEONFALL universe
rather than prioritizing an early playable prototype. Preserve the entire
ambition: 800+ authored major entities, 13 streamed regions, extremely rare
ascension, the One True Omnigod Sovereign and fusion, crafting, world events,
factions, and mobile Fortnite support. Do **not** shrink scope to a small
demonstration, substitute generated titles for playable entities, cap the
backlog to a sample, or invent native UEFN results.

## What this directive changes

The **initial milestone** is a comprehensive, reviewed, *file-backed source
delivery* for every planned major entity, all regions, and the cross-universe
systems. A one-boss playable island is not the finish line and must not be
used to declare AEONFALL complete.

The existence of an authored concept, schema, Verse skeleton, Blender/GLB
preview, or green Python workflow does not equal a complete Fortnite game.
Native UEFN compilation, asset/Character Definition binding, cooked memory,
multiplayer and Fortnite-mobile testing remain independent mandatory release
requirements. These cannot be truthfully finished without using the actual
UEFN editor; they will occur **after** the creator's preferred source-wide
production push, or sooner only if explicitly approved. We may still use
offline asset-generation, unit tests and CI continuously. Those are not
playable prototypes.

### Live baseline: source-audited, not a claim of completed gameplay

At the time of creating this plan the 26 catalog waves contained **840
major-entity definitions**. All were at the `specified` catalog stage.
This exceeds the original 800 minimum but is primarily *design coverage*.
The canonical world topology describes **13 regions**. Existing original
source examples include the Ossuary Exchange geometry/landscape, Omnigod
mesh/skin/animation/audio source pipeline, and Verse gameplay infrastructure.

The canonical implementation ledger has 53 selected entity records and eight
system records, with **zero** verified UEFN imports/Verse compilation or
Launch Session successes. The new universe-wide reviewed-delivery registry
starts empty deliberately: old original source assets continue to exist,
but are not automatically credited as 840 reviewed entity packages or
13 production-complete regions.

The comprehensive auditor, `tools/audit_universe_readiness.py`, enumerates
**every canonical entity ID**, every region, and every required cross-universe
system. Its JSON includes all IDs rather than a small representative sample.
Re-run it for the latest counts; do not rely on this baseline indefinitely.

None of the 840 design entries is implicitly a unique game-ready mesh or
implemented ability. Every entry requires a production source package tied
to its canonical ID. Family-specific source delivery categories are defined
in `content/implementation/universe_first_policy.json`. They include

A source package may reuse proven family infrastructure; unique signature
behavior, silhouette, presentation and acquisition cannot be mere reskins
of generic stock. Shared tooling is acceptable, fake count inflation is not.

### Production workstreams

**A — Complete armory and progression.** Create and source-validate all 180
weapons, 120 armor pieces/sets, 45 relics, 30 classes/skills and 25 vehicles.
Every entity needs its own identified gameplay function, earned acquisition
route, silhouette, at least one differentiated signature, telegraphs and
counterplay. Track native-limited features explicitly rather than asserting
unsupportable player cosmetics or weapon types.

**B — Full living ecosystem.** Produce all 170 monster, 60 wildlife,
64 NPC, 80 boss, and eight faction source packages. Build reusable AI
families with distinct per-entity schedules, threat perception, attacks,
movement, mortality, drops, faction actions, tame/hire behavior, navmesh and
spawn/streaming limits. High-tier world bosses use distributed encounter
brains and authored hit/weakpoint/phase components, not a continent-sized
collision capsule.

**C — Every region and world event.** The 13 world regions need
distinct terrain, landmarks, habitats, encounter placement, quest arcs,
navigation, World Partition/streaming plans, VFX/audio and mobile LOD packages
before source delivery is considered complete. All 58 authored world-event
entities need regional scopes, triggers, bounded consequences, cancellation,
reset and cleanup. Transitions cannot strand players, keep unlimited entities
loaded, or bypass progression.

**D — Crafting, economies and earned ascension.** Complete resource ledgers,
drops, refinement, crafting, Axiom Heart costs and the entire 10-trial route;
persist only canonical, bounded player data. Preserve Transcendent Zero as a
chosen-few objective, not an ordinary farmable item. The owner-only Omnigod
class remains separately gated by trusted native authorization.

**E — The One True Omnigod Sovereign.** Produce and refine the 13-plate
biomechanical source rig toward a genuine humanoid/creature locomotion rig,
combat, specialized armor, creator-only abilities and cinema. FUS-001 Armor
Fusion and experimental FUS-002 Titan proxy remain distinct. Never imply
UEFN permits arbitrary player skin replacement or native NPC possession.
Bound resources, camera cleanup, owner revocation, and damage/line-of-sight
must be proven before activation.

**F — Cross-platform production assets.** For every relevant region, boss,
faction and entity: texture/mipmap policy, skeletal/animation export,
Niagara source design, spatial/priority audio, subtitles, readable
non-color-only telegraphs, touch input affordances, reduced-flash mode,
asset HLODs/LODs, per-region NPC/VFX concurrency plans, and scalable mobile
fallbacks. These must be designed throughout production rather than
added after a desktop-only universe is constructed.

**G — Runtime and packaging.** Integrate persistence, faction standing,
economy, events, portals, quest checkpoints, combat, encounter directors,
taming/hiring, streaming lifecycle and logout/rejoin. Maintain one canonical
source of truth per authoritative system. No unbounded resources, alternate
owner tokens, duplicate runtime singletons or bypasses. Keep all existing
branches and unrelated authored work intact.

## Enforceable completion gates

**Gate 1 — Catalog scope.** All 840 currently authored IDs remain unique
and structurally complete, each original family minimum is met, and the
13 regions remain canonical. Expansions may increase the count; no automatic
entity/sample ceiling.

**Gate 2 — Source deliveries.** Every catalog ID has a separately reviewed,
real-file-backed source package with the family-specific categories in the
policy. Every region has all nine required source categories. Every required
cross-system has runtime, integration, verification and mobile-fallback
artifacts. Any missing file, duplicate entry, unknown ID or false provenance
must fail the audit. A reviewed source package does **not** earn a native
`implemented` or `tested` status.

**Gate 3 — Integrated source universe.** Canonical cross-system contracts
compose without identity, resource, inventory, phase, entitlement,
serialization, cleanup or concurrency conflicts. Run full repository
tests and generated-asset validation on every affected PR. Validate world
streaming topology and mobile fallback assumptions from source. Source
quality and asset content need independent review; automated file presence
alone cannot judge artistic completeness.

**Gate 4 — UEFN native integration (later).** Reinstall/open UEFN on Windows,
create a real project, import all approved assets, compile all Verse,
configure native devices, Character Definitions, NPC spawners, Island
Settings, World Partition, streaming and custom animations. Record exact
compiler output, asset references and UEFN revision in the evidence ledger.
A `.uefnproject` file existing alone is not proof of complete assembly.

**Gate 5 — Full-world gameplay and mobile verification (later).** Native
Fortnite Launch Session, two-client replication, all 13-region transitions,
all economy/progression routes, all boss mechanics, creature interactions,
all 10 trials, owner-only fusion, disconnect/rejoin cleanup and performance
validation. Capture a real cooked publishing-memory measurement and
platform-specific runtime metrics. Epic currently publishes a **300 MiB
cooked publishing memory budget**; the runtime budget varies by platform.
Source arithmetic is not a substitute for that engine measurement.

**Gate 6 — Release approval.** Only after all native evidence is complete
may the project be called production-ready. Publication, private or public,
requires creator approval. Existing disabled-by-default security and
experimental Titan controls stay disabled until their own acceptance passes.

## Source inventory registration

Add *actual* reviewed deliverables to
`content/implementation/universe_source_delivery_inventory.json`.

Each `entity_packs` item has `canonical_id`, `regions` (canonical region
IDs or `GLOBAL`), a `unique_visual_key`, `sources` (category to an array
of real relative repository paths) and `source_review` with
`state: approved_source`, `reviewer` and nonempty `evidence`. Assets
cannot be credited if the referenced files do not exist. The identical
`sources` and `source_review` scheme applies to `region_packs` with
`region_id`, and `system_packs` with `system_id`. In both cases each
required category must have real reviewed artifacts.

The auditor reports all missing IDs in full in JSON. Do not copy one
placeholder mesh to 840 entries to game the gate. A source review is not
native evidence; source-only files must not write `native_uefn_verified`
or `publicly_playable` claims.

## Decisive interpretation

**The creator does not want AEONFALL reduced to an early prototype.**
Engineering should complete the fullest possible original source universe
and keep the entire backlog visible. However, **UEFN-complete** cannot be
declared purely from repository files. Unreal compilation and mobile
gameplay verification are intrinsic to finishing a real Fortnite game
and must eventually be performed with the editor. If engine constraints
require substantial rewrites, maintain the original fantasy while using
supported UEFN representations and document each compromise.
