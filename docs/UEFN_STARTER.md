# Build AEONFALL in the actual UEFN editor

This package contains original modular dungeon geometry, a landscape heightmap, Verse gameplay sources, an installer, and an editor assembly script. The assets and source files are real. UEFN project metadata, cooked assets, the level, and compilation results must be generated by the editor; this Linux build does not contain a fabricated playable island.

## First Windows setup

1. Install Fortnite and Unreal Editor for Fortnite through Epic Games Launcher. In UEFN create an **AEONFALL Blank project**, then save its default level. The editor creates the real `.uefnproject`, project content plugin, and Island Settings.
2. Extract the source package. With Python 3.10+ installed, run `py -3 tools/install_uefn_sources.py "C:\path\AEONFALL.uefnproject" --dry-run`, then repeat without `--dry-run`. The Windows launcher `bootstrap/Install-AEONFALL.ps1` can select the project file. Close UEFN while installing Verse sources.
3. Reopen the project. Enable **Python Editor Scripting** and **UEFN MCP Toolsets** in Project Settings. Enable Python locally in Tools if prompted. Configure MCP auto-start in Editor Preferences, restart, and connect a local MCP-capable agent. Codex CLI configuration is in `bootstrap/uefn.mcp.toml`.
4. Execute `AEONFALLImportPackage/tools/uefn_editor/build_ossuary_level.py` through UEFN's Python execution UI. It discovers your project content mount, imports the modular GLBs, generates UI-supported collision, saves the active map, and assembles `AEONFALL/Maps/OssuaryExchange_Starter`. Repeated execution reuses imported meshes and skips existing named actors.

## SLICE-001 editor contract handoff

The installer now copies the authoritative `content/vertical_slice/` contracts into
`AEONFALLImportPackage/content/vertical_slice/` beside the geometry and editor
scripts. Read `AEONFALLImportPackage/editor_config.json` first: its
`slice_contracts` entries identify the first playable rig, the canonical UEFN
binding inventory, and the 24 Launch Session acceptance cases.

Before writing to the project, the installer checks that the rig's single
BOS-005 director resolves to a canonical encounter, that every physical
encounter role references an existing device of the correct type, that no
physical role is accidentally shared, and that rig dependencies and acceptance
test IDs are consistent. A malformed or incomplete handoff aborts the
installation before any files are copied. The `--dry-run` JSON includes
`slice_handoff.rig_device_count`, `physical_encounter_roles`,
`phase_count`, `launch_test_count`, and the inventory counts for weapons,
monsters, tameables, hireables, encounters and vehicles.

**These are source-contract checks, not editor validation.** The reported
`contracts_validated_editor_unbound` state does not mean any device has
been placed, bound or compiled. The first rig's 49 device records describe
a BOS-005 editor placement task; King Without Pulse and Grave Market Eclipse
remain separate project-bound encounter/event tasks. Do not infer a playable
map from a successful installer run. Use the copied contract files to
configure actual UEFN assets, then record native compiler and Launch Session
evidence separately.

## Assemble the playable loop

The generated level is architecture. Add Island Settings, player spawn pads, lighting and navigation to the new level using the Creative device catalog. The imported scene markers and placement manifest identify checkpoints, boss area and objective anchors; markers in the source manifest are planning coordinates, not automatically spawned Creative devices.

Place one `aeonfall_runtime_tick_device` (a second instance now refuses its session lease rather than doubling time), one profile bootstrap, one actor registry bootstrap, the first-slice combat/class/recipe/reward/shop/taming/hireable/world bootstrap devices, the ability-result router, and unlock delivery router. Compile Verse before placing its generated devices; repair any target-release compiler errors using the actual editor output. The repository's static checks do not replace compilation.

Bind the encounter director to the authored boss, NPC Character Definition/spawner, physical objective anchors, hazards and phase effects. Use its generated canonical contract and exact signal names. Bind one horde ecology adapter per region, its NPC spawner, burn/sanctify buttons, apex event triggers, and evolution presentation graphs. NPCs still need authored Character Definitions and compatible behaviors. **Set a nonempty, exact canonical ID on every NPC lifecycle behavior.** Duplicate registration of the same agent is accepted only when its existing canonical ID and forward/reverse runtime-key mappings agree. In a private Launch Session, deliberately test an unconfigured NPC, repeated registration of one agent, NPC despawn/respawn, and two NPCs sharing a canonical catalog ID; verify that no actor inherits another actor's status, ability, or encounter state. Source guards cannot establish these native lifecycle outcomes.

## Result-router ownership and native acceptance

Place exactly one `aeonfall_ability_result_router_device` and one
`aeonfall_unlock_delivery_router_device`. Each now acquires an exclusive
session lease **before** subscribing to its result channel. A second instance
of the same router rejects startup without touching the active subscription.
The owner cancels its listener before releasing its lease on shutdown; a
rejected duplicate cannot release or cancel the owner's listener. The two
different router types have independent leases.

In a private UEFN Launch Session, deliberately place two instances of each
router, submit one successful and one failed ability effect and one physical
unlock-delivery result, and verify that exactly one authoritative resolution
occurs per request, with no duplicate `*_unresolved` diagnostic from the
rejected instance. End the owner, verify its subscription stops, and start a
replacement to verify it can acquire the released lease. Keep the existing
scheduler running while performing this test; a replacement router does not
auto-start when the old owner ends. Verify player rejoin and timeout behavior
with both routers present. Python source tests cannot establish native
subscription scheduling, Verse compilation or multiplayer behavior.

## Local editor automation mission

With the official UEFN MCP connected on Windows, give the local agent this task:

> Read this source package and `docs/UEFN_AUTOMATION_CAPABILITIES.md`. Discover the live MCP tools with `tools/list`, `list_toolsets`, and `describe_toolset`; use the advertised schemas. Inspect the project and compile Verse. Repair compiler errors without weakening gameplay gates. Run the supplied editor assembly script. Discover and place Island Settings, player spawns and navigation. Place and configure the exact generated Verse devices and first-slice boss/horde bindings. Enable the dev-only assertion devices in a private test map, start a Fortnite session, inspect their results and client logs, fix failures, then disable the harnesses. Validate imported assets, collision clearance and memory. Record actual successful compilation and test evidence in the build report. Do not publish the island.

The cloud session cannot reach your computer's `127.0.0.1`. MCP becomes useful when the local agent and running UEFN editor are connected on the same computer; no public port or credential is needed for this package.

## Acceptance

- UEFN Verse compile succeeds and asset validation passes.
- Archways remain traversable; stair and checkpoint clearance support players and NPC navigation.
- Instant abilities can be used again after cooldown/recharge; stale callbacks cannot spend another request's resources.
- Horde tests and event-before-spawn cases pass in Launch Session; corpse denial and apex limits work with multiple players.
- Boss objectives cannot skip phases, invulnerability windows work, and victory/failure both clear hazards and adds.
- Persistence/rejoin, AI soak, memory calculation and Spatial Profiler checks complete before any production readiness claim.
