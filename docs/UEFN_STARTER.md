# Build AEONFALL in the actual UEFN editor

This package contains original modular dungeon geometry, a landscape heightmap, Verse gameplay sources, an installer, and an editor assembly script. The assets and source files are real. UEFN project metadata, cooked assets, the level, and compilation results must be generated by the editor; this Linux build does not contain a fabricated playable island.

## First Windows setup

1. Install Fortnite and Unreal Editor for Fortnite through Epic Games Launcher. In UEFN create an **AEONFALL Blank project**, then save its default level. The editor creates the real `.uefnproject`, project content plugin, and Island Settings.
2. Extract the source package. With Python 3.10+ installed, run `py -3 tools/install_uefn_sources.py "C:\path\AEONFALL.uefnproject" --dry-run`, then repeat without `--dry-run`. The Windows launcher `bootstrap/Install-AEONFALL.ps1` can select the project file. Close UEFN while installing Verse sources.
3. Reopen the project. Enable **Python Editor Scripting** and **UEFN MCP Toolsets** in Project Settings. Enable Python locally in Tools if prompted. Configure MCP auto-start in Editor Preferences, restart, and connect a local MCP-capable agent. Codex CLI configuration is in `bootstrap/uefn.mcp.toml`.
4. Execute `AEONFALLImportPackage/tools/uefn_editor/build_ossuary_level.py` through UEFN's Python execution UI. It discovers your project content mount, imports the modular GLBs, generates UI-supported collision, saves the active map, and assembles `AEONFALL/Maps/OssuaryExchange_Starter`. Repeated execution reuses imported meshes and skips existing named actors.

## Assemble the playable loop

The generated level is architecture. Add Island Settings, player spawn pads, lighting and navigation to the new level using the Creative device catalog. The imported scene markers and placement manifest identify checkpoints, boss area and objective anchors; markers in the source manifest are planning coordinates, not automatically spawned Creative devices.

Place one `aeonfall_runtime_tick_device`, one profile bootstrap, one actor registry bootstrap, the first-slice combat/class/recipe/reward/shop/taming/hireable/world bootstrap devices, the ability-result router, and unlock delivery router. Compile Verse before placing its generated devices; repair any target-release compiler errors using the actual editor output. The repository's static checks do not replace compilation.

Bind the encounter director to the authored boss, NPC Character Definition/spawner, physical objective anchors, hazards and phase effects. Use its generated canonical contract and exact signal names. Bind one horde ecology adapter per region, its NPC spawner, burn/sanctify buttons, apex event triggers, and evolution presentation graphs. NPCs still need authored Character Definitions and compatible behaviors.

## Local editor automation mission

With the official UEFN MCP connected on Windows, give the local agent this task:

> Read this source package and `docs/UEFN_AUTOMATION_CAPABILITIES.md`. Discover the live MCP tools with `tools/list`, `list_toolsets`, and `describe_toolset`; use the advertised schemas. Inspect the project and compile Verse. Repair compiler errors without weakening gameplay gates. Run the supplied editor assembly script. Discover and place Island Settings, player spawns and navigation. Place and configure the exact generated Verse devices and first-slice boss/horde bindings. Enable the dev-only assertion devices in a private test map, start a Fortnite session, inspect their results and client logs, fix failures, then disable the harnesses. Validate imported assets, collision clearance and memory. Record actual successful compilation and test evidence in the build report. Do not publish the island.

The cloud session cannot reach your computer's `127.0.0.1`. MCP becomes useful when the local agent and running UEFN editor are connected on the same computer; no public port or credential is needed for this package.

## Acceptance

- UEFN Verse compile succeeds and asset validation passes.
- Archways remain traversable; stair and checkpoint clearance support players and NPC navigation.
- Instant abilities can be used again after cooldown/recharge; stale callbacks cannot spend another request's resources.
- Horde tests and event-before-spawn cases pass in Launch Session; corpse denial and apex limits work with multiple players.
- Boss objectives cannot skip phases, invulnerability windows work, and victory/failure both clear hazards and adds.
- Persistence/rejoin, AI soak, memory calculation and Spatial Profiler checks complete before any production readiness claim.
