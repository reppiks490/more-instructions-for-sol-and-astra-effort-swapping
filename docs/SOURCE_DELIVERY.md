# Verified source delivery

Every successful AEONFALL Validation run now creates an `AEONFALL-source-<commit>` GitHub Actions artifact containing `aeonfall-source.zip` and its SHA-256 checksum. The packaging job depends on the validation job and checks out the exact same commit separately, so temporary files generated by tests are excluded.

The inner ZIP contains every committed regular source file, authored asset and document under `AEONFALL/`, plus:

- `SOURCE_MANIFEST.json`: tracked path, Git blob hash, SHA-256 and byte count.
- `CHECKSUMS.sha256`: every source and metadata file.
- `BUILD_PROVENANCE.json`: exact commit, tree and validation run link.

The package refuses modified indexed files, a staged tree different from the committed tree, symlinks, path escapes and duplicate ZIP names. It never includes untracked files or Git credentials. Tests exercise real temporary Git repositories and intentionally corrupt delivery bytes.

The provenance explicitly records editor import, native Verse compilation and Fortnite Launch Session as `not_run`. A successful source-check artifact is a reviewable import package, not an editor-produced playable Fortnite island.

Open the latest successful [AEONFALL Validation run](https://github.com/reppiks490/more-instructions-for-sol-and-astra-effort-swapping/actions/workflows/catalog-validation.yml), expand Artifacts and download the source artifact. GitHub may require sign-in for Actions artifacts. A public exact-commit archive remains available through GitHub's repository archive endpoint and does not include the generated verification metadata.

For a local committed checkout:

```powershell
python tools/build_source_bundle.py --output dist/aeonfall-source.zip
```

This defaults to `source_checks: not_run`; run-linked verification is added by the successful GitHub workflow.

Review this guide when the packaging workflow, archive layout or verification evidence format changes. The implementation is `tools/build_source_bundle.py`, with corruption tests in `tests/test_source_bundle.py` and the dependency gate in `.github/workflows/catalog-validation.yml`.
